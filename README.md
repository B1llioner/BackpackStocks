# BackpackStocks

Монитор акций Backpack RFQ и Jupiter с автоподбором объёма без фиксированного потолка USDC, Telegram-бот, отдельные CLI для котировок и сделок. HTTP Jupiter работает через `curl_cffi` с Chrome TLS/HTTP2 и прокси; точные пакетные расчёты цен и пулов ускорены Rust/PyO3. Основной процесс и Telegram работают на Python 3.12+.

## Быстрая установка

Полная настройка, `.env`, команды и диагностика: **[SETUP.md](SETUP.md)**.

```bash
git clone https://github.com/B1llioner/BackpackStocks.git
cd BackpackStocks
python3.12 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -e '.[jupiter,dev]'
npm --prefix local_clmm ci --ignore-scripts --no-audit --no-fund
cp .env.example .env
# Заполнить .env по SETUP.md: Telegram, Backpack API signing seed, прокси.
.venv/bin/python scripts/setup_jupiter.py --env-file .env
.venv/bin/python scripts/restart_direct_paper.py --config examples/telegram-direct-paper-auto.toml
```

Сначала откройте чат своего Telegram-бота и отправьте `/start`. `/prices` показывает все акции в нескольких сообщениях: цену Backpack RFQ, цену продажи Jupiter, фактически проверенный объём, минимальный выход, наличие RFQ и время обеих котировок по Москве. `/prices WEN` показывает одну акцию. `/spreads` показывает только положительный результат после расходов; `/spread PTN` также ставит выбранную акцию в приоритетную очередь.

Цены и прибыльность считаются отдельно: отсутствие положительного спреда не означает отсутствие котировок. Доступность RFQ кешируется на 60 секунд, для спреда используется только актуальная цена RFQ и DEX (15 секунд в профиле auto). Старые цены в `/prices` отмечены как устаревшие и не участвуют в спреде. Запросы DEX идут по очереди с общим бюджетом провайдера; интервал 10 секунд в конфиге — минимальная цель повторения одной цены. При большом списке акций полный обход дольше, фактический медианный период показывается в `/prices`.

Telegram-кол отправляется для каждого свежего положительного net: по минимальному выходу DEX после стоимости RFQ, удержания комиссии вывода и расходов модели. `policy.min_profit_usdc`, `min_edge_bps` и `max_price_impact_pct` ограничивают автоисполнение, но не скрывают такой расчёт из уведомлений. Ограничение указывается в самом коле. Срок котировки, проверка RFQ, slippage и остальные проверки данных обязательны для уведомления. Cooldown начинается после принятия сообщения Telegram API; истёкший до отправки кол удаляется. События `spread_alert`, `spread_alert_delivered` и `spread_alert_dropped` позволяют отличить найденный расчёт, доставку и сброс. Доставка означает ответ API, а не прочтение пользователем. При закрытой RFQ-сессии `/status`, `/spreads` и `/prices` показывают следующее открытие по расписанию Backpack с учётом часового пояса и праздников.

В профиле auto `monitor.auto_size = true`: 1000 USDC — стартовая точка поиска, а не потолок. Монитор увеличивает проверяемый размер, сравнивает меньшие объёмы и уточняет лучший net после расходов. Минимум и максимум количества берутся из активной RFQ-сессии; отказ провайдера на большом объёме ограничивает следующие пробы. Для спреда выше 1000 USDC дополнительного фильтра по стоимости нет. Профиль `telegram-direct-paper-1k.toml` сохраняет прежний фиксированный объём, если он нужен. Это поиск лучшего проверенного объёма, а не гарантия глобального максимума. `/optimize PUSA` запускает отдельный проход по этим размерам, уточняет соседние и повторно запрашивает лучшую котировку. Цена Backpack проверяется RFQ именно на выбранное количество; устаревшие результаты используются только для выбора следующего запроса.

`/watch <адрес Solana>` включает публичное отслеживание; `/wallet` или `/wallet PUSA` показывает сделки, объём, USDC, комиссию, время и ссылку. Кошелёк и все найденные token accounts подписаны на публичный поток `logsSubscribe` с уровнем finalized. Уведомление сохраняется в SQLite и сразу ставится на проверку через HTTP `getTransaction`. Параллельно каждые 20 секунд работает HTTP-проверка кошелька; обход token accounts сохраняется для восстановления пропусков при разрыве потока. Новые подтверждённые операции приходят в Telegram и ставят акцию в приоритет на пересчёт. История и очередь уведомлений сохраняются в `state/wallet-watch.sqlite3`; котировки монитора для сопоставления сохраняются на 7 дней. Продажа после вывода из Backpack сама по себе не доказывает прибыль: цена покупки на бирже на цепочке не видна.

По умолчанию запускается **paper**. Монитор создаёт и отменяет неисполняемые `AwaitAccept` RFQ для проверки наличия цены. Доступная RFQ означает наблюдавшуюся котировку на указанную сторону/количество, а не гарантированное исполнение новой заявки. Live-покупки и обмены выполняются отдельными CLI с явными флагами и лимитами.

В Git не включаются `.env`, ключи, базы аккаунта, журналы, браузерные записи и рабочие исследования. `.env.example` содержит только пустые поля и учебные значения. Для Rust: `.venv/bin/python -m pip install maturin` и `.venv/bin/maturin develop --release --manifest-path rust/pool-math/Cargo.toml --features python,pyo3/extension-module` при активированной `.venv` и установленном Rust.

## Проверки

```bash
.venv/bin/pytest -q
.venv/bin/ruff check src tests scripts
.venv/bin/mypy src/backpack_stocks
cargo test --manifest-path rust/pool-math/Cargo.toml
```

Публичные RPC/DEX-фикстуры находятся в `tests/fixtures`, поэтому основные тесты работают из чистого клона. PostgreSQL-проверки требуют отдельного opt-in и собственного каталога данных. Конфигурации paper и live-шаблоны лежат в `examples`; live требует собственной настройки лимитов, адресов и ключей.
