# BackpackStocks

Монитор акций Backpack RFQ, spot-стаканов и DEX с автоподбором объёма без фиксированного потолка USDC, Telegram-бот, отдельные CLI для котировок и сделок. Профиль auto считает точные котировки напрямую из состояния пулов Raydium. Альтернативный HTTP Jupiter сохраняет `curl_cffi` с Chrome TLS/HTTP2 и прокси; точные пакетные расчёты цен и пулов ускорены Rust/PyO3. Основной процесс и Telegram работают на Python 3.12+.

## Быстрая установка

Полная настройка, `.env`, команды и диагностика: **[SETUP.md](SETUP.md)**.

```bash
git clone https://github.com/B1llioner/BackpackStocks.git
cd BackpackStocks
python3.12 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -e '.[jupiter,dev]'
npm --prefix local_clmm ci --ignore-scripts --no-audit --no-fund
cp .env.example .env
# Заполнить .env по SETUP.md: Telegram, Backpack API signing seed, прокси.
.venv/bin/python scripts/setup_jupiter.py --env-file .env
.venv/bin/python scripts/restart_direct_paper.py --config examples/telegram-direct-paper-auto.toml
```

Сначала откройте чат своего Telegram-бота и отправьте `/start`. `/prices` показывает все акции в нескольких сообщениях, отдельно **Backpack → Jupiter** и **Jupiter → Backpack**: цены, фактически проверенный объём, стоимость, выход, итог после расходов в USDC и процентах, доступность RFQ каждой стороны и время котировок по Москве. `/prices WEN` показывает одну акцию. Для покупки на Backpack видны итог по quote и консервативный итог с запасом slippage. Для покупки на Jupiter выручка Backpack считается только на минимальное количество полученных акций с округлением до лота; лишние акции не засчитываются в выручку. `/spreads` показывает положительные расчёты; при их отсутствии указывает число актуальных расчётов в каждом направлении. Отсутствующий или устаревший расчёт не объявляется убыточным. `/spread PTN` также ставит выбранную акцию в приоритетную очередь.

Цены и прибыльность считаются отдельно: отсутствие положительного спреда не означает отсутствие котировок. В paper auto полное покрытие **Backpack → DEX** использует публичный поток [`stockIndicativeQuote`](https://docs.backpack.exchange/#tag/Stocks/operation/stockIndicativeQuote), который публикует обе limit-цены раз в секунду. Публичная цена не подтверждает баланс или исполнение RFQ: Backpack пересчитывает цену при поступлении заявки. `/prices` помечает этот источник, а положительный кол требует собственного `AwaitAccept` RFQ на точное количество и повторного расчёта net по его цене. `estimatedAsk`/`estimatedBid` не используются как гарантированные цены.

Каждая акция получает отдельную проверку минимальной допустимой партии независимо от большого объёма, отказов другой стороны и прибыльности. Для первичной публичной проверки paper-бот берёт первый полностью проверенный свежий маршрут на точное количество, без ожидания медленных альтернатив; это результат проверенного маршрута, а не доказательство отсутствия прибыли на всех пулах. Поиск лучшего маршрута, включая разделение объёма, идёт отдельно. Готовый маршрут пересчитывается локально из текущих банков пулов; на том же маршруте проверяются несколько законных объёмов, начиная с четверти, половины и полного текущего бюджета. `/monitor` различает свежие публичные расчёты, расчёты с подтверждённым RFQ, отсутствие текущей цены, ожидание данных DEX и неподтверждённые единицы токена. Первичный обход не считается текущим численным покрытием. Доступность RFQ кешируется на 60 секунд; исходный TTL цены Backpack остаётся 15 секунд, банков DEX — 8 секунд в профиле auto. Старые цены отмечены как устаревшие. HTTP 429 соблюдает серверный cooldown; при отсутствии указаний Backpack выдерживает 60 секунд без новых запросов вместо каскада коротких повторов.

Монитор параллельно использует RFQ и открытые **SPOT/STOCK USDC** стаканы Backpack (`monitor.spot_books = true`). Perp-рынки исключены: их нельзя вывести как акцию. Стаканы обновляются каждые 2 секунды (`monitor.spot_refresh_s`); стоимость покупки и выручка продажи считаются по уровням на всё количество, с taker-комиссией из API аккаунта в USDC и резервом округления. Уровни за пределами taker price-impact band и консервативных limit-price границ исключены из исполнимой глубины. Вход выбирается по стоимости доставленной акции на проверенном размере; выход — по большей проверенной выручке. Закрытая RFQ не блокирует действующий стакан. Доступные рынки обнаруживаются заново; наличие стакана не предполагается для всех акций.

Для покупки по стакану API-ключу нужен доступ к чтению аккаунта и `GET /api/v1/account/limits/order`: проверяются доступное количество, сторона и крайняя цена без займа. Неполная глубина, неизвестная комиссия, недостаточный USDC-баланс или устаревшая проверка исключают такой кол. В auto-режиме отказ по балансу сразу уменьшает покупку до разрешённого API количества на сетке лота и повторно проверяет лимит; свежая граница баланса ограничивает следующие пробы покупки. После ожидания Jupiter и при каждом отчёте стакан пересчитывается заново на то же количество. `/prices` и колы помечают источник «BP стакан», показывают время котировок; RFQ-доступность отображается отдельно. Spot-ордер не отправляется, автоматическое исполнение этой ветки не включено. Акции с неподдерживаемым scaled UI множителем токена не участвуют в спреде; ошибка соответствия единиц показана в `/prices`.

Направления проверяются независимо и чередуются при первом проходе. Отказ RFQ покупки не исключает RFQ продажи. В обратном маршруте акция сначала покупается на Jupiter, затем переводится и зачисляется на Backpack: расчёт по стакану не требует уже имеющихся акций или USDC на Backpack. Он явно помечен как условный после зачисления, учитывает дополнительный модельный gas перевода, доступность и минимум депозита. Цена стакана за время перевода может измениться. RFQ продажи всё равно требует собственного действующего `AwaitAccept` на точное количество; без него RFQ-выручка не публикуется. Обратный расчёт и положительный кол не означают готовность к автоматической сделке; обратное автоисполнение выключено.

Telegram-кол отправляется для каждого свежего положительного net: по минимальному выходу DEX после стоимости RFQ или стакана с taker-комиссией, удержания комиссии вывода и расходов модели. `policy.min_profit_usdc`, `min_edge_bps` и `max_price_impact_pct` ограничивают автоисполнение, но не скрывают такой расчёт из уведомлений. Ограничение указывается в самом коле. Срок котировки, проверка RFQ, slippage и остальные проверки данных обязательны для уведомления. Cooldown начинается после принятия сообщения Telegram API; истёкший до отправки кол удаляется. События `spread_alert`, `spread_alert_delivered` и `spread_alert_dropped` позволяют отличить найденный расчёт, доставку и сброс. Доставка означает ответ API, а не прочтение пользователем. При закрытой RFQ-сессии `/status`, `/spreads` и `/prices` показывают следующее открытие по расписанию Backpack с учётом часового пояса и праздников.

В профиле auto `monitor.auto_size = true`: 1000 USDC — стартовая точка поиска, а не потолок. Монитор увеличивает проверяемый размер, сравнивает меньшие объёмы и уточняет лучший net после расходов. Минимум, максимум и шаг количества берутся из RFQ-сессии или фильтров стакана и доступной глубины; отказ провайдера на большом объёме ограничивает следующие пробы. Для спреда выше 1000 USDC дополнительного фильтра по стоимости нет. Профиль `telegram-direct-paper-1k.toml` сохраняет прежний фиксированный объём, если он нужен. Это поиск лучшего проверенного объёма, а не гарантия глобального максимума. `/optimize PUSA` запускает отдельный проход по этим размерам, уточняет соседние и повторно запрашивает лучшую котировку. RFQ запрашивается на выбранное количество; цена стакана считается по доступным уровням и комиссии; устаревшие результаты используются только для выбора следующего запроса.

`/watch <адрес Solana>` включает публичное отслеживание; `/wallet` или `/wallet PUSA` показывает сделки, объём, USDC, комиссию, время и ссылку. Кошелёк и все найденные token accounts подписаны на публичный поток `logsSubscribe` с уровнем finalized. Уведомление сохраняется в SQLite и сразу ставится на проверку через HTTP `getTransaction`. Параллельно каждые 20 секунд работает HTTP-проверка кошелька; обход token accounts сохраняется для восстановления пропусков при разрыве потока. Новые подтверждённые операции приходят в Telegram и ставят акцию в приоритет на пересчёт. История и очередь уведомлений сохраняются в `state/wallet-watch.sqlite3`; котировки монитора для сопоставления сохраняются на 7 дней. Продажа после вывода из Backpack сама по себе не доказывает прибыль: цена покупки на бирже на цепочке не видна.

По умолчанию запускается **paper**. Монитор создаёт и отменяет неисполняемые `AwaitAccept` RFQ для проверки наличия цены. Доступная RFQ означает наблюдавшуюся котировку на указанную сторону/количество, а не гарантированное исполнение новой заявки. Live-покупки и обмены выполняются отдельными CLI с явными флагами и лимитами.

В Git не включаются `.env`, ключи, базы аккаунта, журналы, браузерные записи и рабочие исследования. `.env.example` содержит только пустые поля и учебные значения. Для Rust: `.venv/bin/python -m pip install maturin` и `.venv/bin/maturin develop --release --manifest-path rust/pool-math/Cargo.toml --features python,pyo3/extension-module` при активированной `.venv` и установленном Rust.

Кол содержит тикер и направление, **чистый спред в USDC и процентах**, фактический объём покупки в USDC, количество акций и время обновления. Прямые ссылки открывают страницу акции Backpack и нужную пару Jupiter; направление `sell`/`buy` меняется для обратной связки. `/prices` содержит эти ссылки и объём для подробного сравнения. Предпросмотр ссылок в Telegram выключен.

## Прямые пулы

Локальные расчёты CLMM распределены между четырьмя обработчиками официального SDK; это не увеличивает лимит RPC-запросов. При TTL банков 8 секунд следующее чтение текущих минимальных маршрутов начинается через 4 секунды от получения RPC-данных, включая время последующей проверки SDK. Их набор tick-массивов определяется всеми минимальными партиями, использующими банк; большие пробы не расширяют этот набор постоянно. Нехватка ticks ставит полное проверенное расширение в отдельную фоновую очередь; локальный расчёт не обращается к RPC. Расширение сохраняется, пока все текущие владельцы не пересчитаются на новом банке. Общие банки нескольких текущих минимальных покупок Backpack обновляются раньше одиночных. Сохранённые альтернативы и большие маршруты обновляются фоном раз в 30 секунд; запрос котировки по ним отдельно требует свежего банка с тем же TTL 8 секунд. Общая очередь выбирает приоритет с учётом доступного соединения и разрешённой частоты непосредственно перед HTTP-запросом. Ожидание или ошибка обновления не продлевают свежесть прежнего банка. Неудачный или прерванный поиск пула не считается завершённым пятиминутным поиском; повтор ограничен нарастающей задержкой и серверным cooldown, который сохраняется и для поиска другой акции.

Для готовой минимальной партии новая публичная цена Backpack меняет стоимость покупки и net сразу, без повторного вызова SDK, если количество, правила и свежие банки DEX остались прежними. При изменении банков маршрут пересчитывается в отдельной ограниченной очереди без сетевых запросов, даже когда поиск маршрутов занял все обычные места. После ожидания DEX применяется последняя действующая публичная цена BP. Эти пересчёты не меняют исходное время банков или TTL. Предварительный отбор по spot-ценам проходит с фоновым приоритетом. Telegram-сводка показывает лучшие свежие пары: спред цены и net в процентах, net в USDC и фактический объём, включая отрицательные результаты. Полная диагностика покрытия доступна через `/monitor`, все акции и объёмы — через `/prices`.

Планировщик проверяет общие входы один раз для пакета запусков без промежуточного ожидания; каждый фактический расчёт повторно проверяет свежесть и точное количество. Фоновые обновления статуса объединяются до одного полного снимка в секунду. Новый потенциальный подтверждённый положительный кол вызывает немедленную проверку для Telegram; `/prices` и `/monitor` строят текущий результат по запросу. При доставке положительный кол ещё раз проверяется на свежесть.

Результат проверки общего календаря торгов переиспользуется в пределах одной секунды UTC при неизменных метаданных. Изменение календаря, граница секунды или откат часов требуют новой проверки; дробные границы времени проверяются точно без этого кэша. Свежесть метаданных, действующие правила партии и обе цены проверяются отдельно при каждом расчёте.

Если все выбранные пулы минимальной продажи отказывают именно по ликвидности, выполняется ограниченное обновление списка: текущие пулы, проверенные on-chain, идут перед историческими ссылками. Число выбранных пулов и cooldown поиска сохраняются. Повторный расчёт выполняется только при изменении списка; таймаут или устаревшая котировка не запускают смену пулов.

В `telegram-direct-paper-auto.toml` включён `monitor.quote_backend = "execution"` при `dex_backend = "raydium"`: точные котировки не требуют API Jupiter. `direct.via_sol = true` проверяет обе стороны пары акция/USDC и полный путь через акция/SOL и SOL/USDC. `direct.split_pools = true` дополнительно сравнивает разделение объёма 25/75, 50/50 и 75/25 между двумя пулами и, для продажи, между прямым USDC-путём и путём через SOL. Это ограниченный поиск, а не обещание глобально лучшего маршрута.

Каждая ветка использует свежие on-chain резервы, комиссии, mint extensions, CLMM ticks/bitmap, динамические комиссии и целые raw amounts. Для маршрута время котировки берётся по самой старой ветке. Spot-цена пары с SOL используется только после пересчёта через свежий SOL/USDC-пул из того же RPC bank; она не считается готовой выручкой. RPC-чтения веток объединяются в пакеты. Сетка объёмов проверяется отдельно от быстрого прохода минимальных партий и использует общий проверенный снимок пула с исходным временем. Повтор того же точного объёма на неизменном банке использует ограниченный кэш расчёта; новый банк, другая сторона, объём или slippage требуют нового расчёта. Кэш не меняет slot, время чтения или TTL. Истёкшая во время расчёта RFQ перепроверяется на то же количество акций. TTL, gas, slippage и условия депозита Backpack сохраняются.

Изменение числа tick-массивов, нужных большому объёму CLMM, не запускает повторное обнаружение адресов для готовой минимальной партии. При обновлении эти адреса и полный банк заново проверяются; изменение канонического набора возвращает полное обнаружение. Расширенный банк для большего объёма сохраняется в общем кэше до расчёта количества. Завершившийся старый запрос не может откатить этот банк, его slot или время к предыдущему снимку.

Пулы из успешных swap-инструкций отслеживаемого кошелька сохраняются как адреса для discovery в игнорируемый `state/watched-pools.json`. Владельцы программ и пары проверяются через RPC; сохранённая цена не используется для следующей котировки. Новые акции берутся из проверенной метадаты Backpack. Пулы Raydium обнаруживаются по API при отсутствии нужной пары. Кол содержит фактические пулы и ссылки на их аккаунты. Поддержаны Raydium CLMM/CPMM; сделки через Meteora, Orca, Manifest и другие DEX не объявляются воспроизведёнными этим роутером.

Прямой одиночный swap доступен в `backpack-direct`; многопуловые и двухшаговые маршруты сейчас доступны для оценки, их автоматическое исполнение выключено до реализации отдельного атомарного builder. Котировка не загружает signing key. Для возврата к frontend Jupiter задайте `monitor.quote_backend = "jupiter"`; реализация `curl_cffi` и прокси остаётся доступной.

```bash
.venv/bin/backpack-direct --config examples/telegram-direct-paper-auto.toml quote --symbol PUSA.US --direction sell --amount 100
```

Одиночный прямой круг SOL → акция → SOL, сначала только симуляция:

```bash
.venv/bin/python scripts/direct_sol_round_trip.py --symbol WEN.US --usdc-value 10
# Реальная покупка и последующая продажа только купленного количества:
.venv/bin/python scripts/direct_sol_round_trip.py --symbol WEN.US --usdc-value 10 --execute
```

Используется локальный `SOLANA_WALLET_KEY`, свежий SOL/USDC spot для размера входа и прямой пул акции/SOL. На каждой стороне есть minimum output, проверка симуляции и комиссии; временный WSOL-счёт закрывается в той же транзакции. Результат считается по finalized изменениям баланса, включая комиссии и rent. Это проверка обмена, круг может быть убыточным. Журнал `state/direct-native-swaps.sqlite3` и состояние `state/direct-sol-round-trip.json` защищают от повторной покупки. При прерывании используйте `--execute --resume` для исходного круга; неизвестная отправка сверяется по исходной подписи. Для нового отдельного круга явно задайте новый `--state`.

## Проверки

```bash
.venv/bin/pytest -q
.venv/bin/ruff check src tests scripts
.venv/bin/mypy src/backpack_stocks
cargo test --manifest-path rust/pool-math/Cargo.toml
```

Публичные RPC/DEX-фикстуры находятся в `tests/fixtures`, поэтому основные тесты работают из чистого клона. PostgreSQL-проверки требуют отдельного opt-in и собственного каталога данных.
